# Ответы на 10 вопросов по Java

## 1. Порядок выполнения блоков инициализации
**Вывод:** A D B C E B C

**Объяснение:**
1. A: Статический блок выполняется один раз при загрузке класса.
2. D: Начинается метод main.
3. B: При вызове первого new Demo() отрабатывает нестатический блок.
4. C: Затем выполняется конструктор.
5. E: Следующая строка в main.
6. B и C: При втором new Demo() снова отрабатывает нестатический блок, затем конструктор.

## 2. Модификаторы доступа при наследовании в разных пакетах
* **В классе Child (пакет b, наследник):** Доступны члены Parent с модификаторами public и protected.
* **В классе из пакета b (не наследник):** Доступны только public члены. Модификатор protected не работает без наследования, а package-private не виден вне пакета a.

---

## 3. Sealed-класс и record-наследники
**Важно:** Создать sealed class, у которого наследники — record, нельзя. Классы record неявно наследуются от java.lang.Record, а множественное наследование классов в Java запрещено.

Вместо этого нужно использовать **sealed interface**.
**Преимущество в switch:** Это дает исчерпываемость (exhaustiveness). Компилятор знает все возможные реализации интерфейса, и вам не нужно писать ветку default.

## 4. String Pool и метод intern()
**Вывод:**
false
true
false

**Объяснение:**
* Переменная a указывает на строку "Hello" в String Pool.
* Переменная b создана через new, это новый объект в куче (Heap), вне пула. Поэтому a == b это false.
* Метод intern() ищет такую же строку в пуле (которую создала a) и возвращает ссылку на нее. Теперь c ссылается на тот же объект, что и a. Поэтому a == c это true.

## 5. Конфликт default-методов (Diamond Problem)
**Почему не компилируется:** Возникает конфликт. Компилятор не понимает, какую реализацию hello() выбрать для класса C — из A или из B.
**Как исправить:** Класс C обязан переопределить метод:
class C implements A, B {
@Override
public void hello() {
A.super.hello(); // Явный вызов реализации из A
}
}

## 6. В чём разница между StringBuilder и StringBuffer?
* **StringBuilder:** Не потокобезопасен, работает быстро. Используется в 99% случаев.
* **StringBuffer:** Потокобезопасен (методы синхронизированы), работает медленнее.
  **Сценарий для StringBuffer:** Несколько разных потоков (Threads) одновременно дописывают текст (например, логи) в одну общую строковую переменную. StringBuffer гарантирует, что данные не перемешаются.

## 7. Лямбды и замыкания
**Вывод:** 10

**Объяснение:** Лямбда захватывает локальную переменную x. В Java такие переменные должны быть "effectively final" (фактически финальными — их нельзя изменять после инициализации).
**Если раскомментировать x = 20:** Код не скомпилируется с ошибкой "local variables referenced from a lambda expression must be final or effectively final".

---

## 8. Пример лямбды, которую нельзя заменить на ссылку на метод
    Function<Integer, Integer> math = x -> x * 2 + 5;

**Почему:** Ссылка на метод (например Math::abs) работает только если лямбда просто передает аргумент в существующий метод. Здесь мы выполняем математические операции, для которых нет отдельного готового метода.

---

## 9. Чем EnumMap быстрее HashMap?
**Внутренняя реализация:** EnumMap представляет собой простой Java-массив, где индексом выступает порядковый номер (ordinal) константы enum. Это дает мгновенный доступ к элементам без вычисления хеш-кодов и без коллизий.

---

## 10. Особенности record Point(int x, int y)
* **Что сгенерирует компилятор:** Приватные финальные поля x и y; конструктор со всеми аргументами; геттеры x() и y(); методы equals(), hashCode() и toString().
* **Можно ли добавить изменяемое поле?** Нет. Все поля состояния внутри record являются неявно final.
* **Можно ли наследоваться от record?** Нет. Классы record являются неявно final и не могут иметь наследников.
